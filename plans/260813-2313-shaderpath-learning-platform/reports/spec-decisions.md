Resolves ambiguities/contradictions in `prompt-webgl-learning-platform.md`.
**These decisions OVERRIDE the spec where they conflict.** Spec §1 tech stack otherwise stays fixed ("không thay thế").

## D1 — GLSL imports: raw asset source, not `vite-plugin-glsl`

**Spec §8.5** says shaders live in `.glsl` files, imported "qua `vite-plugin-glsl` hoặc raw loader".
**Conflict:** `vite-plugin-glsl` is a Vite plugin; the app is Next.js (webpack/turbopack). Unusable as written.

**Decision:** import `.glsl` as raw source string.
- webpack: `config.module.rules.push({ test: /\.glsl$/, type: 'asset/source' })` in `next.config.ts`.
- turbopack: equivalent rule entry (`turbopack.rules['*.glsl'] = { loaders: [...], as: '*.js' }` or the `asset/source` equivalent supported by the installed Next version — verify against the version resolved in Phase 1).
- `types/glsl.d.ts`: `declare module '*.glsl' { const src: string; export default src }` (plus `.vert`/`.frag` if used).

**Intact from spec:** no shader strings inline in JSX/TSX.
**Not adopted:** `#include`/chunk composition in the loader — out of scope; compose in TS at call site if a lesson needs it.
**Phases:** 1 (config + types), 4, 5, 7, 9 (consumers).

## D2 — MDX: `@next/mdx` + explicit typed import registry

**Spec §1** allows "next-mdx-remote hoặc @next/mdx" — undecided.

**Decision:** `@next/mdx` (build-time compile, RSC-friendly, no runtime MDX eval, cheaper hydration).
- Pipeline: `remark-math` → `rehype-katex` → shiki (GLSL grammar; dual light/dark theme wired to next-themes) → `rehype-slug` + TOC extraction (Phase 3).
- Per-locale lesson resolution goes through an **explicit typed import registry** generated from `curriculum.ts` (`content/lesson-registry.generated.ts`, `Record<LessonSlug, Record<Locale, () => Promise<MDXModule>>>`).
- **No magic dynamic-import template strings** (`import(\`../content/lessons/${slug}/theory.${locale}.mdx\`)`) — turbopack cannot statically analyze them, and they defeat type safety.
- Registry regenerated by `pnpm gen:registry`; CI/precommit check that it is in sync.

**Phases:** 2 (generator + pipeline), 3 (consumer).

## D4 — Monaco GLSL: custom Monarch tokenizer

**Spec §1** claims `@monaco-editor/react` "có syntax highlight GLSL". **False** — Monaco ships no GLSL grammar.

**Decision:** register a custom language `glsl` in one file under `components/playground/` :
- Monarch tokenizer (keywords, types `vec2..4/mat2..4/sampler2D`, qualifiers `uniform/varying/attribute/in/out/precision`, swizzles, preprocessor `#version/#define/#ifdef`, comments, numbers incl. float suffix).
- Completion provider for GLSL built-ins (`mix, clamp, step, smoothstep, fract, mod, length, distance, normalize, dot, cross, texture, ...`) + the platform's default uniforms (`uTime`, `uResolution`, `uMouse`).
- Language config: brackets, auto-closing pairs, comment tokens.

**Phases:** 5 (also serves `shader` exercises in 6).

## D5 — `bookmarks` table: full definition

**Spec §5** leaves `bookmarks` as a comment stub.

**Decision:**
```ts
export const bookmarks = sqliteTable('bookmarks', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  lessonSlug: text('lesson_slug').notNull(),
  anchorId: text('anchor_id'),
  label: text('label'),
  createdAt: integer('created_at', { mode: 'timestamp' }).notNull(),
});
```
`anchorId` nullable = whole-lesson bookmark. `label` nullable = fall back to heading text at render time. Index on `lesson_slug`.

**Phases:** 1 (schema/migration), 8 (feature).

## D6 — Content strategy: Track 0 as golden sample, Phase 9 as sub-iterations

**Spec §9** phases 4–6 need sample content; phase 9 is "write Tracks 2→13" with no acceptance criteria.

**Decision:**
- Phases 4, 5, 6 build their systems against **the first lessons of Track 0** as the golden sample (plus the Track 1/Track 2 demos required by §9 phase 4's "3 demo mẫu ở Track 0–2"). No throwaway fixtures — sample content is real content that survives into Phase 7.
- Phase 9 (~110 bilingual lessons) is a **marathon, executed one track per session**, each track a self-contained sub-iteration: author → content lint → self-review → commit → stop. Never attempt multiple tracks in one sitting; quality drift is the primary failure mode.
- Track order stays 2 → 13 (dependency order of the curriculum).

**Phases:** 4, 5, 6, 7, 9.

## D9 — Curriculum granularity: mental-model lessons, modules with checkpoint builds, core/elective tiers

**Spec §4** lists ~131 bullets; plan initially assumed 1 bullet = 1 lesson. Brainstormed + researched 2026-08-13, user approved Option B ([brainstorm report](brainstorm-260813-lesson-granularity.md)).

**Decision:**
- **Lesson = 1 mental model, 20–45 min** (theory + demo + ≥1 exercise completable in one short session). Merge §4 bullets when each is <10 min and one worked example covers both (e.g. dot+cross+normalize). Split when intrinsic load jumps (e.g. quaternions split off Euler/gimbal-lock).
- **Module = 3–5 lessons + 1 checkpoint** — a mini-build lesson (`kind: 'checkpoint'`): no new theory, one `build` exercise with checklist synthesizing the module. **Track = 2–4 modules.**
- **`LessonMeta` gains** `tier: 'core' | 'elective'` and `kind: 'lesson' | 'checkpoint'`. Elective ≈ 15–20% (quaternion depth, SPH fluids, PBR math depth, TSL, …): full senior depth preserved, but never blocks unlock; dashboard/roadmap shows electives separately.
- **Unlock logic counts core lessons only.** Roadmap renders **module-first** (progress ring per module; lessons on expand) — the learner sees 13 tracks / ~40 modules, never a flat ~160-item list.
- **Exercise rule amended (overrides §3.2 "≥3 per lesson incl. build"):** regular lesson ≥2 exercises (1 `concept` + 1 `code`); `build` work concentrates in module checkpoints. Checkpoint lessons: ≥1 `build` exercise with checklist; citations optional; theory section = brief goal/requirements only. Track 13 capstones are checkpoint-shaped (resolves former open question 4).
- **Estimated totals:** ~100 core + ~20 elective + ~35–40 checkpoints ≈ 155–165 units in ~40 modules. Final counts locked during Phase 2 metadata authoring — slugs freeze there (churn breaks notes/bookmarks anchors).

**Phases:** 2 (types, metadata, roadmap, unlock), 7, 9 (authoring + lint rules), 8 (dashboard elective split).
